# Git 差异打包工具

Windows x64 桌面应用，使用 Tauri 2、TypeScript 和 Rust。选择项目所在目录，可按日期或从上次成功打包的提交开始，一次预览多个 Git 仓库的净变更，并按原目录结构导出 ZIP。

## 使用

1. 在 Windows 上安装 Git for Windows，并确保在新开的终端中运行 `git --version` 能看到版本号。运行应用安装包，安装到当前用户账户。
2. 打开「Git 差异打包工具」，选择一个仓库的根目录，或选择多个仓库的共同上级目录。
3. 首次选择「按日期」，设置起止日期，或切换为分钟精度。点击「预览差异」，核对仓库、分支、两个提交和文件变更。
4. 点击文件名打开代码对比。左栏显示起始快照，右栏显示结束快照，两侧显示行号并高亮变化。工具栏可跳到上一个或下一个差异，也可切换文件。按 Esc 返回文件列表。
5. 点击「导出 ZIP」，在保存对话框中选择位置。预览有扫描错误时，先处理界面中列出的路径和错误，再重新预览。

代码对比按需读取当前文件的两个 Git 版本。新增文件显示右栏内容，删除文件显示左栏内容，纯改名显示新旧路径。支持 UTF-8 和带 BOM 的 UTF-16 文本，每侧上限为 2 MiB。二进制、其他编码或更大的文件会显示状态，仍按原始字节参与导出。

## 从上次打包继续

1. 在 1.2.0 中按日期成功导出一次 ZIP。应用会将每个有结束提交的仓库实际打到的完整提交号保存为锚点。旧版 ZIP 没有记录这些提交号。
2. 再次选择同一打包目录，切换为「从上次打包」。默认比较到各分支最新提交；取消最新提交选项即可选择截止日期或分钟。点击「预览差异」可核对每个仓库的起止提交。
3. 成功导出后锚点向后续提交推进。取消保存、导出失败、没有可打包文件时，保留原锚点。补打历史日期的包也会保留较新的进度。

进度按所选目录、仓库和分支分别保存在当前用户的应用数据目录。新增仓库或切换到没有锚点的分支时，请用日期模式建立锚点。如果旧锚点已经脱离当前分支的第一父链，日期预览会列出需要重建的仓库；核对后勾选确认并成功导出，才会替换这些锚点。界面若提示 ZIP 已保存但锚点更新失败，应核实此次 ZIP，处理提示后重新预览。

## 预览时检查远程

日期模式和锚点模式都会先展示本地差异，再检查各仓库当前分支配置的上游。仓库名下会显示同步、领先、落后或分叉状态及相应提交数。即使选择历史截止日期，上游检查也会使用扫描时的本地分支最新提交。检查只提供提示，ZIP 和锚点仍以本次本地预览为准；要纳入远程新提交，请自行拉取后重新预览。

每个窗口最多同时检查 3 个仓库，每个仓库的时限为 20 秒。分离 HEAD、未配置远程上游、无法认证或网络不可达时，会显示原因，仍可查看本地差异和导出。检查使用临时 Git 仓库按需读取上游对象，复用用户已配置的非交互凭据或 SSH 密钥，不改动工作区、当前分支和远程跟踪分支。

## 文件如何选取

- 各仓库独立使用当前分支或分离 HEAD 的第一父链。以提交者时间计算左边界前和右边界内的最后一个提交，比较它们的文件树。结束日期的整天或结束分钟的整分钟均包含在范围内。没有起始提交时使用空树，历史不足的浅克隆会提示错误。
- 新增和修改文件导出结束快照中的完整内容，改名导出到新路径。预览中可查看删除路径和改名前的路径，解压覆盖后需自行清理这些旧路径。
- 范围内改过又还原的内容自动排除。工作区、暂存区或预览之后的新提交不会改变已经预览的结果。
- ZIP 保留仓库相对于所选目录的位置和仓库内路径。直接选中仓库时，从仓库根目录开始。ZIP 只包含文件，不附变更清单。
- 按 Git 存储的原始字节导出。Git LFS 文件导出为已提交的指针文件，符号链接导出为含目标路径的普通文本文件。已检出的子模块作为单独的工作区扫描，父仓库的子模块提交指针不会写入 ZIP。扫描不会跟随工作区中的目录链接或联接点。

## 从源码运行

使用 Windows x64、Node.js 22.12 或更新的 LTS 版本、Git for Windows、Rust stable MSVC、带 x64 C++ 工具与 Windows SDK 的 Visual Studio Build Tools，以及 WebView2 运行时。首次构建需联网获取依赖及 NSIS 打包工具。

在包含 `package.json` 的目录中执行：

```powershell
npm ci
npm run tauri dev
```

构建安装包：

```powershell
npm run tauri build -- --bundles nsis
```

安装程序生成在 `src-tauri/target/release/bundle/nsis/`。项目提供 `package-lock.json` 和 `src-tauri/Cargo.lock` 锁定依赖版本。

运行前端检查及真实 Git 仓库集成测试：

```powershell
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --tests
```
